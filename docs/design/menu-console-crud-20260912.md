# 菜单控制台全量增删：删除即持久删除（软删墓碑）

> 状态：**已落地**（2026-09-12）
> 决策日期：2026-09-12
> 上游文档：[seed-identity-key-20260912.md](seed-identity-key-20260912.md)、[seed-authority-scope-revision-20260912.md](seed-authority-scope-revision-20260912.md)
> 一句话结论：菜单的**字段**早已交还运维，但**行的存在性**仍归种子——新增/删除被拒写。本次把"菜单行"也交还运维：控制台可新增根菜单/子菜单、可删除任意菜单（含内置菜单），删除通过在菜单表留下**软删墓碑**让种子不再复活它。

---

## 背景：为什么之前禁止增删

`seedMenus` 的职责是"按 `seed_key` 认行、缺失时创建"。这条规则对**新增**没问题（新菜单会被创建，`role_menu` 授权不受影响），但对**删除**是致命的：

| 操作 | 旧行为 | 后果 |
|---|---|---|
| 控制台删除内置菜单 | 下次启动种子发现"缺失" → 重建 | 删除被静默撤销；重建的行 `id` 变了，`role_menu` 授权丢失 |
| 控制台新增菜单 | 被 `MenuBuiltInCreateDeleteForbiddenError`(100606) 拒写 | 功能扩展/调整只能改代码发版 |

结果是"菜单管理"页对内置应用只有编辑权：**页面改名改路径可以，增删不行**。而业务上"加一个页面入口 / 下线一个页面"恰恰是最常见的诉求，被逼回"改 `seedMenus` + 发版"。

## 决策

### 1. 新增：任何应用都可增，自建行 `seed_key` 恒为空

- 放开 `Create`，删除 `rejectBuiltinAppMenuCreateOrDelete` 守卫与错误码 100606。
- 控制台自建行 `seed_key = ''`；种子只按 `seed_key`（兼容存量库的 `(app_id, code)` 兜底）认行，**永远不会认领自建行**。
- 保留原有的"应用内 `code` 唯一"约束（`uk_menu_app_code_active` 部分唯一索引兜底）。

### 2. 删除：软删行即墓碑，种子不再复活

控制台的删除是软删除（`deleted_at`），软删行仍带 `seed_key`——这正是"该内置菜单已被人为下线"的**墓碑**：

```
seedMenus 认行顺序：
  1) seed_key（active）     → 命中则复用
  2) seed_key（含软删）      → 命中即墓碑，跳过创建（Warn 日志）
  3) (app_id, code) 兜底    → 仅存量库回填 seed_key 用
  4) 都没有                 → 新建
```

**墓碑检查必须早于 `(app_id, code)` 兜底**：否则运维删除内置菜单后自建一个同 `code` 的菜单，会被兜底分支误认领并回填 `seed_key`，运维自建行当场被"变成"内置行。

删除是**持久**的：被删的内置菜单不会再被种子建回来，也不会重新获得 `role_menu` 授权。要"重新上线"，在控制台新建即可（新的行 `seed_key` 为空，种子不接管）。

### 3. 退役菜单（版本级下线）不留墓碑

`retiredMenus` 的清理改为**物理删除**（`Unscoped()`）：退役是版本级动作（定义已从 `seedMenus` 移除），与运维级删除是两种语义。若退役也留软删行，未来版本重新上线同名 `seed_key` 时会被墓碑挡住，永远创建不出来。

### 4. 删除级联子树 + 解绑角色授权（事务）

菜单树从 `parent_id = ''` 构建，父级一旦删除，其子菜单不会再出现在任何应用的菜单树里——只会变成"看不见又删不掉"的孤儿行。因此：

- `Delete` 先按应用取回菜单集合、内存遍历出 `rootID + 全部子孙`（菜单树规模有限，避免逐层查询）；
- 在同一事务内：逐个菜单解绑 `role_menu`（防悬空授权）→ 软删菜单行；
- 前端二次确认文案"其子菜单将一并删除"自此名副其实。

### 5. 上级菜单校验（新增/修改）

放开增删后，层级错误会直接产出孤儿行或成环：

- 父级必须**存在**且与菜单**同属一个应用**（跨应用父级在任何应用树里都不成立）；
- 父级不得是**自身或其子孙**（成环后整棵子树从菜单树消失，等于自删）。

违反返回本领域功能级错误码（`MenuCreateError` / `MenuUpdateError`），系统错误与业务边界判断分离。

### 6. 种子对"父级不可用"的降级

若某内置菜单的父级已被删除、而它自己还在（手工删库等非级联路径），种子**跳过该子菜单并 Warn 日志**，不再返回 `parent not found` 中断启动，也不把它改挂成根菜单（种子的层级定义不该被静默改写）。`seedRoleMenus` 对缺失菜单同样跳过。

## 影响面与升级路径

| 维度 | 结论 |
|---|---|
| 存量库 | 无 schema 变更，仅行为变更；`seed_key` / 部分唯一索引沿用 |
| 删除的持久性 | 由软删墓碑承担，无需新表；被删行保留在 `menu` 表中（软删） |
| 重新上线内置菜单 | 控制台新建（`seed_key` 为空，种子不接管）；或开发者按"旧 `seed_key` 登记 `retiredMenus` + 新定义"两步走 |
| 接口契约 | 无新增/变更字段；`DELETE /v1/platform/menus/{menuID}` 语义由"单行删除"变为"级联删除子树" |
| 错误码 | 删除 100606 `MenuBuiltInCreateDeleteForbiddenError`（常量 + 文案 + 前后端引用一并删除） |
| 前端 | 菜单页解除"新建根菜单/新增子级/删除"的置灰与隐藏，移除"内置应用不可增删"提示 |

## 风险与回滚

| 风险 | 触发 | 应对 |
|------|------|------|
| R1 误删平台自身入口 | 运维删掉「菜单管理」等内置菜单 | 内置管理员角色豁免授权、菜单页可按 URL 直达，仍可恢复；删除有二次确认并提示级联 |
| R2 内置菜单删除后前端路由仍在 | 删的是"页面入口"而非页面本身 | 属预期：菜单是入口配置，页面代码随版本发布 |
| R3 重新上线同名 `seed_key` 被墓碑挡住 | 开发者把已退役/已删菜单重新加回 `seedMenus` | 退役走物理删除不受影响；运维删除的需先在控制台新建，或人工清理软删行 |
| 回滚 | 需回到"内置菜单不可增删" | 恢复 100606 守卫与前端置灰即可；墓碑列（软删行）无害，可保留 |
